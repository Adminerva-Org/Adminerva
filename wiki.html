School setup: connect students, sections and teachers

For administrators. Use the same section name throughout setup, including spaces and punctuation. A section name connects student roster records with teacher assignments.

  1. Check the existing roster names. Open Sections (administrator) and review the current names listed from student records. Keep those names when the roster is already in use.
  2. Maintain the section catalog. Add the exact class names under Sections. For example, use Grade 11 ICT A consistently. Creating a catalog entry does not enroll students.
  3. Enroll or link students. In User directory (administrator), import a roster or approve a student request using the student's verified email and exact section name. Check the email carefully; it must match the account the student uses to sign in.
  4. Authorize teachers and assign their sections. Open Teacher assignments (administrator), enter the instructor's verified email, select their sections explicitly, and save with a reason. Authorization allows the teacher to sign in; section assignments scope supported teacher views, including Class analytics.
  5. Reload and check the teacher view. Ask the teacher to reload open pages, choose their section and check the student list. An assigned section stays empty until student records use that same name. Existing learning snapshots may need a separate refresh.

Tracks & pathways (administrator) and Subjects (administrator) describe the school's offerings. These catalogs do not enroll students, assign teachers or grant teacher access.

In Account settings (staff), connection keys and integration preferences belong to the signed-in staff account. The application Firebase details are read-only and reflect the deployed school connection.

Release versions

New releases use MAJOR.MINOR.PATCH, with dates separately. Major means substantial or incompatible changes, minor adds compatible capabilities, and patch focuses on fixes. Earlier dated identifiers remain valid for links and read notifications. Private drafts are not public releases and send no notices. Browse published updates.

From assignment to grade: a step-by-step guide

There are two submission methods. Adminerva Studio sends a saved copy of a coding project. GitHub repository evidence uses selected commits to show your individual contribution. Your teacher chooses the method when creating the assessment. You do not need to learn both at once.

For teachers: set up an assessment

  1. Open Assessment Studio and select Create assessment.
  2. Enter a title, task instructions, maximum score and grading quarter. Read the prepared rubric and edit it for your task.
  3. Choose Adminerva Studio project snapshot for projects completed in the browser, or GitHub repository evidence for commit-based work. This choice is protected once saved.
  4. Save the assessment, open it and select Deploy. Choose the class, opening date and deadline. Confirm the displayed schedule before assigning it.
  5. Use Studio submissions or Review & Grade for the matching submission method. Inspect the student's actual submitted work, save a private score, and publish it from Gradebook when ready.

For students: complete a Studio assessment

  1. Open My Assessments. Choose the assignment to see its instructions, rubric and deadline.
  2. Select Open Adminerva Studio. Create a named project or open one you own. Work in Code, Design or Database as the task requires; save your work before submitting.
  3. Select Submit for assessment. Confirm the correct assignment and project name. Adminerva sends a fixed copy of the files, diagrams and data.
  4. Return to My Assessments. Look for the revision number and status. If the connection fails, check the submission status before pressing Submit again.
  5. When a teacher requests a revision, make changes and submit again. Your previous submitted version remains available for review. Only a published grade appears as your result.

Example: A student named their Java project “Library Manager.” They fix a search bug after submitting revision 1. That new code is not included until they submit revision 2.

Practical exams in Adminerva Studio

  1. Teacher: Choose a Studio assessment, tick Practical exam — restrict copying and pasting code, save and deploy it. Explain the exam rules and permitted resources before students begin.
  2. Student: Open the assignment from My Assessments and follow its Studio link. A yellow exam notice appears while normal code clipboard, import, previous-version and AI helper controls are restricted.
  3. Student: Type and run your work. Save your named project. Submit the fixed project revision while the assessment remains open.
  4. Teacher: Review the submitted revision, ask the student to explain their decisions when needed, and publish the final score after review.

Limit: A web browser cannot prevent screenshots, external devices, developer tools or code written before an exam. The restrictions discourage simple copy-and-paste; they do not prove cheating. Never automatically penalize a student based only on a browser event. Use a supervised setting and a clear school policy for high-stakes exams.

Project Hub and evidence

  1. Open an assessment. Expand instructions or the rubric when needed.
  2. Select committed changes that represent your own work and choose a pinned checkpoint. Shared project source is context, not proof that every member contributed.
  3. Submit your selected evidence. If a submitted selection needs changing, check whether the teacher has returned or reopened it first. Withdraw only if that control is available and you intend to cancel the pending submission. Clearing an unsaved selection does not erase a submitted record.
  4. After approval, ask the instructor to reopen evidence. Protected or published grades require deliberate instructor revision; earlier evidence remains in the audit history.

Review and Grade

  1. Review: inspect selected diffs and matching checkpoint source within the workspace. Verify individual contributions and approve evidence, or reopen it with a reason.
  2. System evaluation draft: select Evaluate when requirements are met. Check coverage and criterion explanations. Copy a suggested score or feedback only if you agree.
  3. Teacher score and feedback: enter or revise your own judgement, save a private draft, then separately confirm publication. Saving does not automatically publish.

How AI can affect a grade: Auto Checker or an external AI provider may prepare a suggested score or feedback when enabled by the instructor. The result can be wrong or incomplete. Teachers are responsible for reviewing evidence, deciding the grade and publishing it. Students should be told when automated assistance was used and can ask for clarification of the published feedback.

Adminerva Auto Checker provides automated assistance. Evaluation details identify its origin, provider where applicable, and limitations. A draft is not an instructor-approved grade. Missing teammate screens must not automatically lower an individual's contribution score, and shared screens cannot earn credit for a noncontributor. A single XML file cannot establish the completeness, functionality or authorship of an entire application.

Playground, XML Layout Lab and Practice

Adminerva Studio is available to visitors and signed-in learners across supported languages. Edit and run code, organize files and folders, import or export a ZIP, and save device drafts. Signed-in account features remain separate from public previews. Save or export work before leaving. XML Layout Lab translates a supported subset of Android layout XML into a sandboxed browser preview; full Android resources, constraints and runtime behavior require Android Studio.

Practice Lab: one mission pool

Explore the Practice Lab with 300 shared missions in Java, Python, web interfaces, and debugging/logic. Activities include choosing an answer, writing an exact answer, ordering statements, matching pairs, and fixing a bug. Visitors can preview the same missions and experiment in Playground. A verified signed-in student, approved staff member or eligible pending guest can submit scored answers and save current-season progress.

Only selecting Submit scored answer counts as a graded practice attempt and changes that mission's possible reward. Opening missions, changing draft answers, running code, compiler errors and connection failures do not deduct points. The server records mistakes across reopened attempts, respects the minimum reward, and awards each mission once per season. Replays cannot add more points. Practice Points do not change school grades or establish independent authorship or mastery.

The global leaderboard is optional and displays aliases, season points and completed-mission counts. Use a nickname instead of a real name, school name or email. Your class board remains private. Authorized teachers can view roster names alongside current-season totals in Practice analytics. Earlier completions, original 10-XP records and separate teacher reviews remain preserved as earlier history; they are not silently converted into the new scoring season.

Changing an active scored device requires confirmation and, when needed, a recent sign-in. Saved points remain intact. Shared devices are supported; moving a practice session does not create an automatic cheating penalty. Browser drafts remain separate from acknowledged server saves.

Lesson Planner and Slide Editor

Save a lesson, open its Slide Editor link, and create an editable starter. Private lesson remarks are excluded. Source version details help identify lesson changes; existing slide edits are not silently replaced. Inspect and edit each slide before classroom use. The editor is not a full Canva-style design suite.

Practice session privacy

Scored practice uses a resettable random browser key, not a hardware fingerprint, to control session transfers. Neutral handover records are kept separately from optional activity sharing and never establish misconduct. Attempts expire after two hours, session leases after thirty minutes, and handover events after thirty days; deletion may occur later through the configured expiry policy. Earned progress and unique-mission award receipts remain separate. No system can establish who physically answered solely from a device change.

Two kinds of analytics

Teacher Analytics focuses on academic progress, reviewed practice and assigned students' optional coarse engagement snapshots. Administrators can select a configured instructor in this same teacher view. Administration Analytics focuses on usage, returning visits and support. Raw diagnostic activity and system bug management are not teacher analytics. Manage Teachers controls audited instructor admission and assigned teaching sections. Teachers see only assigned academic records and credential-free roster copies; old shared records may require administrator preparation. Administration Analytics and Teacher Analytics are separate pages; administrators use Class analytics to inspect an instructor’s teaching view.

Time means approximate active foreground use, not time spent learning, attendance or effort. Repeated visits mean returning on different UTC days within the observed window, not a validated retention rate. Samples, consent gaps, idle detection and offline use make these numbers incomplete. Never grade or discipline students based on these signals alone.

Optional hourly maintenance can refresh non-grading summaries and remove bounded batches of expired monitoring records. Both policy switches default off. An administrator must separately activate the backend and review privacy, costs and retention; a saved checkbox does not prove a worker is installed. The dashboard shows its last recorded server result.

Optional activity sharing

Open Account Settings → Activity & privacy. Home-page reminders can be hidden without enabling sharing. Sharing is off by default. If you enable it, Adminerva sends module identifiers, a small set of actions, approximate active seconds, your account/student identifier and timestamps. It does not collect typed text, source code, passwords, full URLs, mouse coordinates or session recordings. Guests are not tracked by this feature.

A separate optional diagnostic switch keeps at most 20 allowlisted actions in memory on the current page. To share that trail, explicitly tick the attachment box when sending a report to the administrator. Teachers do not receive that trail. Stopping sharing blocks new events immediately. If the optional backend consent handler is installed, it removes the student's rows from the latest teacher snapshot when the change is processed; otherwise an administrator must refresh the snapshot. It does not erase earlier raw records. Contact your administrator for deletion. Events and trails carry 30-day expiry timestamps; expiry alone is not deletion. Separately activated cleanup is bounded and can leave a backlog; manual cleanup or approved server retention policies may also be needed. Account preferences and latest teacher summaries are stored separately. Device preferences should be disabled before using a shared computer.

Loading and reporting a problem

The global status indicator describes work still in progress; it is not a guarantee of success. Wait for the page's completion or error message. If a process fails, preserve unsaved work, then retry. Report system bugs to an administrator and class concerns to a teacher. Include the module, expected result and reproduction steps. Remove names, credentials and unrelated private information from screenshots. Adminerva does not deploy permission changes or publish grades automatically.

Teacher accounts and personal planning

Administrators authorize verified teacher emails through Manage Teachers and assign their learning-analytics sections. Admission does not send an invitation email. Teachers sign in with the authorized email and save their own lessons, timetables, slides and planning defaults. Administrators can inspect retained teaching records; students cannot open staff planning files.

Save your work before switching accounts. If another tab saved a newer version, keep your text and reload before replacing it. Older shared lessons remain read-only for administrator review. Importing an older shared timetable copies it into your editor only; review it and save deliberately into your own account.

Teacher Analytics defaults to published scores. Private-draft charts are provisional and missing scores are not zero. Optional activity does not establish effort or mastery. Operational reports and diagnostic trails belong to administrators.
